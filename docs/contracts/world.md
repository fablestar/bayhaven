|---|---|---|

| a zone file | `{ id, name, bounds, seed, roads: { lines }, rows, kit, hoods, hero, reserved, promenade, landmarks, places, generator, traffic, peds, ambience, palette }` · optional `split(block, addLot, { rng, hash2, overlap })` · optional `plazas: [rect]` | A road line is `{ id, pid, name, axis: 'ns' or 'ew', at, from, to, kind, width or widths, closed, parts }`. `parts: [{ from, to, id, name, kind }]` renames a stretch of a line (Coral Boulevard becomes Kapok Street). `pid` prefixes piece ids when two districts share a road id. A zone with `split` cuts its own blocks into lots (Meridian); without it the map uses Tideline's rule. `plazas` stand at kerb height even where they cover a closed street. A hood may carry `z0, z1` as well as `x0, x1`. Where a line of one zone ends on the same point as a line of the next, the map joins them with a seam node (`seam: true`, no cross street), so neither is a stub |
| a lot | `{ id, zone, hood, block, recipe, kit, x0, x1, z0, z1, face, sides, seed, floors, h, wall, body }` · hero lots add `hero`, reserved sites `reserved` · tower lots add `tiers` and `crown`, `mast`, `corner`, `plaza`, `helipad` | Footprint (`body`), height and wall colour are fixed in the map, so the full building, its far shell and the skyline agree. A tier is `{ x0, x1, z0, z1, y0, y1, col, plain, round, rot, top, noRoof }`: `gen/towers.js` `drawTiers(o, tiers, { cell, inset, cut })` draws it the same way in all three rings |
| a road piece | `{ id, roadId, name, kind, axis, ax, az, bx, bz, len, width, lanes, speed, level, a, b, stub }` | `a` and `b` are junction keys (`'x,z'`), or null at a dead end; `stub` pieces end at a barrier and carry no lanes |
| modules.chunks | `isLoaded(cx, cz)` · `loadedCount` · `pending` · `ensure(x, z, radius) → Promise` · `buildMs` · `stats()` · `resetStats()` · `reset()` · `decor` · `skyline { mesh, triangles, towers, tall, landmarks, top, beacon, update(seconds, on) }` | The streamer. | a hero lot, `landmarks/<id>.js` | `export default { id, skyline, build(o, lot, map), shell(o, lot, { inset }) }` | Hand-written pieces: `day1-block`, `lifeguard-hut`, `spire`, `cityhall`. With `skyline: true` its `shell` is also drawn into the skyline mesh (it must then write only to `o.W`) |

It stops width / 2 + 2 short of each junction. A walking edge is `{ id, kind: 'walk' or 'crossing', ax, az, bx, bz, len, next: [edges], crossing }` |

| modules.gulls | `{}` | Gulls over the beach |

Allowed import from another lane: `landmarks/day1-block.js` and `block.js` import `createParkedCar` from `src/vehicles/models.js`.

Test API entries: `test.chunks()` (the streamer's numbers), `test.ensure(x, z, radius)`, `test.city() → { triangles, towers, tall, landmarks, top, beacon, on, litTo, stats }` (the skyline, how far the lights are on, how high the lit floors reach in metres, each generator's counters).

Events I emit: `district:entered { id, was }` (map), `chunk:loaded` and `chunk:unloaded { cx, cz, lod }` (chunks). `prop:broken` is still emitted by vehicles.

Events I listen to: `game:reset` (props stand back up), `quality:changed` (the city is built again at the new detail).

`?day=1`: `block.js` is day 1's whole block, built as it was, with nothing streaming. It is there so day 1's numbers can still be checked.

Stand-ins I left: none. Not yet matching the bible: the nav graph is built once for the whole map instead of per chunk (it is pure data and small); `map.heightAt` ignores `level` (no decks yet); walking edges do not check lights.
